# MCP

# 为什么需要 MCP？

MCP 是一个万能接口，统一的调用方式，相当于 SpringCloud 的 OpenFeign，MCP 是用于大模型应用与外部工具 / 数据源之间的调用，是对 ToolCalling 进一步的加强版，这个是 A2A 的基础。

实际上 MCP 看起来就是一堆 ToolCalling 的集合，比如百度地图的 MCP 包含了

# MCP 的两种模式

# STDIO

客户端会启动一个子进程来运行 MCP 服务器。两者通过操作系统的标准输入流和标准输出流来交换 JSON-RPC 格式的消息。

# SSE

SSE 是一种基于 HTTP 的轻量级推送技术。MCP 的 SSE 模式通常采用双向通信：

  1. 客户端通过 HTTP 向服务器发送请求（如调用工具）。
  2. 服务器通过一个持久的 SSE 连接向客户端主动推送响应或事件。
  3. 这就实现了客户端与远程服务器之间的实时、异步通信。

# LangGraph

# 什么是 LangGraph

LangGraph = LangChain + 图编排 + 状态机

LangGraph 是一个用于构建有状态、多步骤 AI 智能体应用的框架，它通过将流程建模为节点和边的图结构来编排大语言模型。它内置了持久化与循环控制机制，适合开发复杂、可恢复的对话和任务执行系统。

LangGraph 可以理解为更加底层的 LangChain，可以实现更加细节的控制。

LangGraph 的核心就是把程序拆成 节点（做事的步骤）、边（步骤之间的连线） 和 状态（共享的数据）。

它按 Superstep（超级步） 来运行：每一轮从所有待执行的节点同时开始，节点跑完后更新状态，再根据边决定下一轮执行哪些节点。

把它想象成流水线：每一步只关心 “当前拿到什么状态”，做完交给下一步，直到没有下一步可走。

在 LangGraph 里，边分两种：

  • 普通边：固定从 A 走到 B，没有选择。
  • 条件边（路由）：根据当前状态决定下一步去哪。比如一个函数返回 "tools" 或 "end" ，图就根据这个返回值把流程送到不同节点。

所以路由的作用就是：执行完某个节点后，根据状态动态选择下一个节点。

# LangGraph 两种 API 对比

Functional 写起来快，Graph 控制力强。两者底层一样，Functional 最终也是编译成 Graph 执行。

Functional 适合进行原有的项目改造，Graph 适合需要精确控制流程的场景。

# 顺嘴一提 Python 的小知识

py 中存在一个、两个、四个短线的名字，那么那些分别是什么东西呢？

  1. xxxx ：公开属性，外部可以自由访问
  2. _xxxx ：受保护的属性，约定不要外部直接访问，但是不做直接强制
  3. __xxxx ：私有属性，Python 会自动改写名称（ _类名__xxxx ），防止外部访问
  4. __xxxx__ ：魔法属性，比如 __init__ ，是 Python 的内置特殊属性，不要随意定义这类名

魔法属性：它们不是让你直接调用的，而是由 Python 解释器在特定场景下自动触发的。你可以把它们理解为 Python 对象的 "钩子"（hooks），让你能自定义对象在各种内置操作中的行为。
