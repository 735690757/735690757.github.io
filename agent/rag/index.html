# 文本分块

question：为什么要文本分块？

  1. Embedding Model 有严格的输入长度上限，超出此限制的文本块在输入时都会被截断，导致信息丢失，生成的向量也无法完整代表原文的语义。
  2. LLM 同样有上下文窗口限制，如果单个块过大，可能会导致只能容纳少数几个相关的块，限制了 LLM 回答问题时可参考的信息广度

question：是不是越大越好？

块的大小并非越大越好，过大的块会严重影响 RAG 系统的性能。也就是说可选择的越多，大模型越眼花缭乱，少量且正确的信息反而是关键。ABCDFG 的语义信息明显比 ABC 的语义信息包含的多，因此对 ABC 进行语义匹配的时候 ABC 的排名通常会高于 ABCDFG。

# 递归字符分块 RecursiveCharacterTextSplitter

也可以支持针对不同语言进行分割，这个是对不同编程语言进行了优化：

递归字符分块的原理是采用一组有层次结构的分隔符（如段落、句子、单词）进行递归分割，旨在有效平衡语义完整性与块大小控制。在 RecursiveCharacterTextSplitter 的实现中，该分块器首先尝试使用最高优先级的分隔符（如段落标记）来切分文本。如果切分后的块仍然过大，会继续对这个大块应用下一优先级分隔符（如句号），如此循环往复，直到块满足大小限制。这种分层处理的机制，能够在尽可能保持高级语义结构完整性的同时，有效控制块大小。

# 语义分块 SemanticChunker

断点识别方法 ( breakpoint_threshold_type ):

  1. percentile 百分位法：计算所有相邻句子的语义差异值，并将这些差异值进行排序。当一个差异值超过某个百分位阈值时，就认为该差异值是一个断点。breakpoint_threshold_amount (默认为 95)，表示使用第 95 个百分位作为阈值。这意味着，只有最显著的 5% 的语义差异点会被选为切分点。
  2. standard_deviation 标准差法：计算所有差异值的平均值和标准差。当一个差异值超过 “平均值 + N * 标准差” 时，被视为异常高的跳跃，即断点。breakpoint_threshold_amount (默认为 3)，表示使用 3 倍标准差作为阈值。
  3. interquartile 四分位距法：使用统计学中的四分位距（IQR）来识别异常值。当一个差异值超过 Q3 + N * IQR 时，被视为断点。breakpoint_threshold_amount (默认为 1.5)，表示使用 1.5 倍的 IQR。
  4. gradient 梯度法：这是一种更复杂的方法。它首先计算差异值的变化率（梯度），然后对梯度应用百分位法。对于那些句子间语义联系紧密、差异值普遍较低的文本（如法律、医疗文档）特别有效，因为这种方法能更好地捕捉到语义变化的 “拐点”。breakpoint_threshold_amount (默认为 95)。

# 基于文档结构的分块 MarkdownHeaderTextSplitter

适用于 Markdown、HTML、LaTeX 等极具结构化的内容。

单纯按标题分割可能会导致一个问题：某个章节下的内容可能非常长，远超模型能处理的上下文窗口。为了解决这个问题， MarkdownHeaderTextSplitter 可以与其它分块器（如 RecursiveCharacterTextSplitter ）组合使用。具体流程是：

  1. 使用 MarkdownHeaderTextSplitter 将文档按标题分割成若干个大的、带有元数据的逻辑块。
  2. 对这些逻辑块再应用 RecursiveCharacterTextSplitter ，将其进一步切分为符合 chunk_size 要求的小块。

这个是一个可视化分词工具：https://chunkviz.up.railway.app/

# 向量嵌入

question：Embedding 在干什么？

一句话来讲就是，把文本、图像、音频、视频等转换为数学上易于处理的、低维、稠密的连续数值向量。

如果向量是杂乱的也无意义，经过 Embedding 之后数据是有语义的。通常使用以下数学方法来衡量向量间的 “距离” 或 “相似度”：

  1. 余弦相似度 Cosine Similarity（最常用）
  2. 点积 Dot Product
  3. 欧氏距离 Euclidean Distance

RAG 的语义检索以 Embedding 为核心，流程为：

  1. 先将文档切块并向量化存入向量数据库，查询时将问题也向量化
  2. 再计算问题向量与文档块向量的相似度
  3. 最后召回相似度最高的 Top-K 文档块，作为上下文与问题一起交给大模型生成答案。

Embedding 技术经历了三个阶段：

  1. 静态词嵌入：Word2Vec、GloVe 为每个词生成固定向量，但无法解决一词多义问题。
  2. 动态上下文嵌入：基于 Transformer 自注意力机制，同一个词在不同语境中生成不同向量，有效解决了多义性。
  3. RAG 驱动的新要求：
    • 领域自适应：需通过微调或指令适应专业领域
    • 多粒度与多模态：支持长文档、代码、图像、表格等多样输入
    • 检索效率与混合检索：平衡存储成本与检索速度，结合语义与关键词匹配，如 BGE-M3

# 多模态嵌入

OpenAI 的 CLIP (Contrastive Language-Image Pre-training) 是一个很有影响力的模型，它为多模态嵌入定义了一个有效的范式。

它采用双编码器架构 (Dual-Encoder Architecture)，包含一个图像编码器和一个文本编码器，分别将图像和文本映射到同一个共享的向量空间中。
